## 修复与复测

### F01：重新预览残留上一次加入失败

复现：有效邀请预览 → 确认时邀请过期 → 原面板报错 → 暂不加入 → 恢复邀请 → 再次查看。原实现仅关闭预览，没有清理写操作状态，新预览错误地显示上一轮过期错误。

修复：统一通过 `dismissPreview()` 关闭确定失败/未提交的面板，同时重置写状态。写操作进行中、结果未知时禁止关闭清理；原面板的手动重试仍复用原幂等键。未改变真实接口和服务端错误映射。

先补回归测试，在修复前 iOS/Android 均失败，见 [失败记录](evidence/issue17/regression-before-fix.log)。修复后新增场景通过；原生 A09 → A10 → A11 也通过，详见对应截图和真实请求记录。

### F02：建账名称改正后仍显示旧校验错误

复现：空名称提交后改为合法名称，旧的名称错误仍显示。修复为编辑名称时清理该字段旧错误，下一次提交继续执行完整验证。组件测试确认改正时错误消失、未发建账请求；原生 A02 通过。

### 环境观察：开发会话一次异常

本次长时间热更新会话中，第一次切换乙账号出现登录及 `/me` 200、随后账本列表 401；再登录时列表也曾显示「请先登录」。完整终止并启动开发客户端后，乙通过正常 refresh 恢复、列表 200；其后退出乙再登录甲、列表与详情均 200，A14 通过。

尚未确定这次异常根因，不能据此认定认证代码缺陷已修复，也不能保证仅由热更新造成。保留该观察与请求记录，发布安装包验收时应继续检查跨账号切换；本次未修改认证实现、注入会话或隐藏错误。
