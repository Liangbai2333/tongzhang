# 公共支撑与跨模块规则

## 1 契约与纯计算

`packages/contracts/src/endpoints.ts` 是29个业务接口的登记表；每项包含编号、路径、认证、幂等、请求与响应Schema。各业务Schema分文件维护；通用Schema分为`http.ts`（错误结构、响应包装、分页）、`scalars.ts`（ID、时间、金额字符串、枚举）和`limits.ts`（上限；人数与单笔金额上限源自domain，避免多处硬编码）。JSON为默认传输方式，图片上传使用multipart，读取使用二进制。输出DTO只包含契约声明字段，不直接返回数据库整行。`packages/domain` 仅做整数金额和分摊，不导入Node、数据库或移动端模块。精确结算算法只放服务端settlements/solver.ts。

## 2 事务与锁

写请求顺序：会话 → 参数 → 幂等锁 → 账本行锁 → 角色/状态/版本 → 成员和图片关联 → 写入业务、审计和成功结果 → 提交。事务入口为db/transaction.ts的withTransaction，Repository接受同一Transaction。幂等事务锁入口为db/idempotency.ts；完整用例还必须查询结果、校验请求摘要和保存结果，不能把取得锁当作完整幂等。

读取预览或汇总使用一个SQL快照，或只读REPEATABLE READ事务。业务写事务的lock_timeout为2秒。邀请加入、消费变更、正式结算共同锁同一账本，防止满员及冻结竞争。

## 3 幂等与版本

| 项目     | 规则                                                   |
| -------- | ------------------------------------------------------ |
| 作用域   | 用户 + 方法/规范化资源路径 + UUID键                    |
| 成功结果 | 与业务同事务保存7天                                    |
| 重试     | 原键、原请求；先校验当前身份与访问权限                 |
| 内容变化 | 同键不同请求摘要拒绝；不能盲目生成新键重交             |
| 客户端   | 结果未知且24小时内可手动同键重试；不持久化离线队列     |
| 版本     | 消费编辑校验消费version；影响结算的变化递增账本version |

## 4 审计与错误

`db/audit.ts` 只追加审计；与业务共用tx。日志不记录密码、原令牌、完整图片。结构化错误包含code/message/requestId，字段错误可附fieldErrors。认证失败401、无权403、状态或版本冲突409、格式错误400；内部账务不守恒阻止结算并记录脱敏错误。

## 5 手机端数据状态

HTTP层集中处理鉴权、错误、超时和响应Schema；无离线持久缓存。QueryClient的query/mutation均retry:false、networkMode:always。每个feature查询键必须包含userId；退出、切换账号清空缓存。断网不展示旧业务数据作为可用离线账本。

消费写入成功后失效：账本列表/详情、流水/详情、成员余额、统计、结算预览。正式结算成功后失效：账本详情、结算记录；已还成功后失效：结算进度与余额；归档成功后失效：本人账本列表和历史。页面挂载前在线getMe确认会话。

## 6 数据库所有权

| 数据                 | 写入协调者                                   |
| -------------------- | -------------------------------------------- |
| 用户创建/会话        | auth                                         |
| 用户资料/偏好        | profile                                      |
| 账本、成员、归档     | ledgers；invitations在加入事务内调用成员写入 |
| 消费、分摊、收据关联 | expenses                                     |
| 图片字节与资产校验   | images；业务保存时共享tx绑定                 |
| 正式结算/转账        | settlements                                  |
| 余额与统计           | balances只读派生                             |
| 审计、幂等           | 外层业务service传入同一tx                    |

所有13张表集中由`db/schema/tables.ts`导出，避免相互引用的复合外键散落后产生循环初始化问题。Schema变化先生成迁移、审查SQL，再执行测试库迁移；不在共享环境schema push。

## 7 开发接入约定

`routes.ts` 负责HTTP接入，`service.ts` 控制权限、状态和事务，`repository.ts` 接收同一事务执行数据访问，不自行开启第二个事务。移动端 `api.ts` 接入统一HTTP层，`model.ts` 定义面板状态，`query-keys.ts` 隔离用户查询。表单失败保留输入，提交成功后清空。

每个用例按Repository查询与锁 → Service事务与映射 → 契约、权限和事务测试 → 页面与面板 → 原生联调的顺序接通。替换相应用例的Service占位方法后，移除该接口的骨架说明。
