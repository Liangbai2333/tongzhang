# 账号与会话模块设计

## 1 职责与边界

注册、登录、会话检查、退出；将账号身份交给后续账本权限判断。

A01/A02不使用幂等结果表；断网退出应清本地凭据和所有用户查询缓存，并说明服务端撤销是否确认。

| 项目     | 归属                                               |
| -------- | -------------------------------------------------- |
| 服务端   | `apps/server/src/modules/auth/`                    |
| 移动端   | `apps/mobile/src/features/auth/`                   |
| 共享契约 | `packages/contracts/src/auth.ts` 与 `endpoints.ts` |
| 数据     | users（注册写入）、auth_sessions                   |

## 2 子功能与接口

| 编号 | 操作       | 方法与路径                   | 幂等键 |
| ---- | ---------- | ---------------------------- | ------ |
| A01  | `register` | `POST /api/v1/auth/register` | 不使用 |
| A02  | `login`    | `POST /api/v1/auth/login`    | 不使用 |
| A03  | `logout`   | `POST /api/v1/auth/logout`   | 不使用 |

## 3 调用过程

用户填写账号信息 → 契约校验 → 密码哈希或校验 → 同事务保存账号/会话 → 返回安全用户信息和原令牌。退出仅撤销当前会话。

## 4 数据规则与事务

注册写入users与auth_sessions必须一起提交；邮箱唯一冲突映射EMAIL_TAKEN。登录只创建会话，不创建用户。用户名重名时要求使用邮箱。

使用Argon2id；原令牌仅返回客户端一次，数据库保存SHA-256摘要，固定30天到期。登录、注册限流。密码、令牌不进入日志或幂等结果。

## 5 移动端组织与交互

注册和登录分别为全屏表单；协议用面板；登录错误保留原表单。成功后保存SecureStore令牌，在线getMe核验后进入账本列表。

## 6 开发与验收

建议贯通路径：注册、登录、在线恢复、退出。

验收覆盖：邮箱重复、凭据错误、失效会话、匿名访问；任何失败均不返回密码哈希。
