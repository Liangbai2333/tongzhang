# 图片资产与收据模块设计

## 1 职责与边界

上传受限图片、授权读取、临时资产绑定和清理；客户端选择、压缩与显示。

image_assets使用bytea；不加对象存储或OCR。清理仅针对超过24小时且未绑定无引用资产。

| 项目     | 归属                                                 |
| -------- | ---------------------------------------------------- |
| 服务端   | `apps/server/src/modules/images/`                    |
| 移动端   | `apps/mobile/src/features/images/`                   |
| 共享契约 | `packages/contracts/src/images.ts` 与 `endpoints.ts` |
| 数据     | image_assets；消费模块拥有expense_images             |

## 2 子功能与接口

| 编号 | 操作          | 方法与路径                    | 幂等键 |
| ---- | ------------- | ----------------------------- | ------ |
| A18  | `uploadImage` | `POST /api/v1/images`         | 不使用 |
| A19  | `getImage`    | `GET /api/v1/images/:imageId` | 不使用 |

## 3 调用过程

相册/相机选JPEG或PNG → 客户端压缩 → multipart上传 → 保存未绑定资产 → 保存消费或账本时锁资产并绑定 → 授权读取。

## 4 数据规则与事务

上传单独提交；业务保存失败不能回滚已完成上传。绑定事务核对上传者、kind、未绑定状态、目标账本；原收据可保留，其他消费收据不能挪用。

每笔最多1张、单张≤1048576字节；服务端实际解码/尺寸校验，不能只信扩展名或MIME。未绑定仅上传者可读，绑定后仅账本成员可读。

## 5 移动端组织与交互

选图、预览和失败重试位于原表单；图片读取需携带认证头，不暴露公共下载地址。

移动端的 `api.ts` 提供原生文件上传与受鉴权读取，选图与预览状态由消费或账本表单持有。表单状态只在内存中；失败保留输入、成功才清空；所有写操作禁用自动重试。

## 6 开发与验收

建议贯通路径：封面上传、收据上传与读取。

验收覆盖：伪造MIME、超限/损坏图片、重复绑定、跨用户读取、取消表单后清理、读取响应不缓存。
