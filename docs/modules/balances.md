# 成员余额与支出统计模块设计

## 1 职责与边界

读取一致快照，派生消费总额、个人净额、剩余净额、类别和成员统计。

类别占比是显示数据，不参与账务计算。列表筛选不改变账本顶部总额。

| 项目     | 归属                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 服务端   | `apps/server/src/modules/balances/`                                                |
| 移动端   | `apps/mobile/src/features/balances/`                                               |
| 共享契约 | `packages/contracts/src/balances.ts` 与 `endpoints.ts`                             |
| 数据     | 只读ledgers、ledger_members、users、expenses、expense_splits、settlement_transfers |

## 2 子功能与接口

| 编号 | 操作            | 方法与路径                                 | 幂等键 |
| ---- | --------------- | ------------------------------------------ | ------ |
| A20  | `getBalances`   | `GET /api/v1/ledgers/:ledgerId/balances`   | 不使用 |
| A21  | `getStatistics` | `GET /api/v1/ledgers/:ledgerId/statistics` | 不使用 |

## 3 调用过程

校验账本成员 → 一致快照读取有效消费、分摊、已还 → 按整数分汇总 → 校验守恒 → 组装DTO。

## 4 数据规则与事务

多次查询必须使用同一只读REPEATABLE READ事务，或合并为单一SQL快照。不得写入额外余额表。

消费净额=已付−应摊；剩余净额=消费净额+已还转出−已还转入；全员净额和为0。已还不是消费，消费总额不受其影响。

## 5 移动端组织与交互

余额和统计为独立页面；成员详情使用面板。金额用深色数字，应收/应付使用颜色加文字；查询失败不能伪造0。

## 6 开发与验收

建议贯通路径：记三笔 → 总额300元 → 净额核对 → 已还后余额归零。

验收覆盖：无消费空态、仅部分人参与、已还后总消费不变、软删除过滤、统计百分比0分母、跨账本访问。
