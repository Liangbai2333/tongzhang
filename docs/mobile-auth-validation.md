# 移动端认证实现与验证

日期：2026-10-24。分支：`feat/1-jwt-auth`。关联 [Issue #1 / T03](https://github.com/Liangbai2333/tongzhang/issues/1)，使用 `Refs #1`，验收状态由 PR 审核确认。

## 实现结果

- 默认入口改为真实欢迎、登录和注册流程，路由位于 `app/(auth)`。`app/(app)/account.tsx` 为受保护的当前落点，仅展示真实 `getMe` 用户资料和退出操作；账本仍未接通，明确展示未就绪状态。
- 根 Stack 使用 Expo Router `Stack.Protected`，只有在线核验成功且存在真实用户时放行。冷启动先用 SecureStore 的 Refresh Token 恢复并在线读取用户；后台或断网后隐藏受保护内容，重新核验后才放行。恢复失败在根容器显示原因与手动重试，不新增全屏错误路由。
- 登录与注册使用 React Hook Form，复用 contracts 的校验约束。注册要求确认密码与明确勾选；错误保留输入，提交中禁用输入、重复提交及返回。密码显隐和协议阅读为真实交互。
- `AuthProvider` 通过可独立测试的 controller 管理用户、操作状态和跨导航提示。无凭据、401、会话撤销及迟到响应不会放行受保护页面；JSON 和图片接口继续共用双令牌管理器，业务写请求不自动重发。
- 退出先尝试远端撤销，随后尝试本地删除，并分别报告 `serverRevoked`、`localCleared`。当前页使用确认面板；退出后的反馈在欢迎页保留。远端未确认不显示完整成功，本地删除失败提供手动重试清理入口。会话变化清空用户查询内存。
- 新增 `pnpm test:mobile`，使用 Jest Expo、React Native Testing Library 的 iOS / Android preset；CI 已同步调用。React / React Native 版本未变，新增依赖均为测试或 Babel 开发依赖；`test-renderer` 固定为兼容 React 19.2 的 1.2.0。

## 提交前审查

审查覆盖 JWT 校验、刷新行锁与重放撤销事务、迁移、共享契约、存储串行化、迟到响应隔离、页面准入、真实接口和配置边界。修复两处退出边界：刷新失效引起会话版本变化后，必须依据实际删除成功状态判断 `localCleared`；安全存储必须等新旧两项凭据的删除均结束后才释放串行队列，避免失败后尚未完成的删除影响后续登录。新增 5 个行为用例在两个平台运行，并加强绝对到期测试，使用最新未消费的 Refresh Token 验证到期拒绝。

修复后重跑全部静态检查、79 项无数据库测试、32 项移动端测试和 11 项专用数据库测试，服务端构建、双端 JS 导出、Expo Doctor、依赖及 peer 检查通过。生产镜像重新构建并运行独立容器认证与迁移验证；结果见双令牌验证记录。审查未发现剩余阻塞问题，下面的原生人工验收限制仍保留。

## CI 首次加载超时修复

PR #9 的 [Checks #21](https://github.com/Liangbai2333/tongzhang/actions/runs/40080865511) 在 `pnpm test:mobile` 失败：Android 首个空表单校验用例超过 Jest 默认 5 秒，其余 31 项测试、静态检查、无数据库测试与独立容器检查均通过。使用 Node 24.21.0 Linux 容器、0.5 CPU、CI 环境变量和 `--no-cache` 重现同一用例的 5 秒超时；1 CPU 的冷缓存运行及本机冷缓存运行通过，确认资源受限时的首次 React Native 加载开销会触及默认预算。

将移动端 Jest 全局单项超时明确设为 15 秒，覆盖 iOS / Android 两个项目；保留原有全部断言、查询超时、失败退出行为，不增加测试自动重试。此项仅修改测试配置，不改应用或接口行为。修复后在相同 0.5 CPU Linux 冷缓存环境重跑 32 项测试，并执行 `pnpm check`、`pnpm test` 和常规 `pnpm test:mobile`；远端最终结果以 PR Checks 为准。
