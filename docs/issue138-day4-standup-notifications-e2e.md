## 2. `B11`：`A32 → notifications → A33/A34` 端到端联动核对

在 [notifications.integration.test.ts](../apps/server/tests/notifications.integration.test.ts) 保留 #122 原有 4 项表约束与服务测试的基础上，新增 2 项全程经由真实 HTTP 接口（`A32`、`A28`、`A29`、`A33`、`A34`）驱动的隔离 PostgreSQL 端到端用例，基线提交 `dfe69b4`：

| 核对项                                    | 端到端场景与断言结果                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`notifications` 迁移与约束**            | 在空库 `tongzhang_empty` 连续执行两次 `pnpm migrate:db` 均成功；`\d notifications` 确认 10 列、4 外键（含 `(ledger_id, transfer_id) -> settlement_transfers(ledger_id, id)` `ON DELETE RESTRICT`）、5 项 `CHECK`、3 项二级索引完整；隔离库 `schema.integration.test.ts` 验证 15 表 122 列与二次迁移幂等                                                                                                          |
| **`A32 → notifications` 写入与幂等**      | 以四人“鼓山一日”基准账（`30000` 分，小陈→小安 `3000` 分、小丁→小白 `6000` 分）叠加第二账本「海边夜宵」（`4000` 分）经真实 `POST /api/v1/ledgers/:ledgerId/settlement/transfers/:transferId/remind` 触发多条催还；同 `Idempotency-Key` 重放返回一致响应且不重复写入 `notifications` 行；`amountCents` 全程保持整数分字符串，零消费/转账金额与账本 `version` 改动                                                  |
| **`A33` 跨用户隔离、分页与 `unreadOnly`** | 催还发起人（小安、小白）与无关路人列表均为 `[]`，小陈仅见本人 `3000` 分提醒，小丁跨两账本见 3 条提醒；`limit=2` 游标分页无重无漏；标记其中 1 条已读后，`unreadOnly=true&limit=1` 分页精确返回剩余 2 条未读，而 `unreadOnly=false` 仍完整返回 3 条并携带已读时间戳                                                                                                                                                |
| **`A28` 改名后 `actorName` 实时反映**     | 小白调用 `PATCH /api/v1/me` 改名为「小白改名版」后，小丁调用 `A33` 立即显示更新后的 `actorName`，同时小安发起的提醒保持「小安」，底层 `notifications` 行未被改写                                                                                                                                                                                                                                                 |
| **`A34` 仅接收人本人幂等标记已读**        | 催还发起人（小白）、账本创建者（小安）、同账本其他成员（小陈）及无关路人调用 `POST /api/v1/me/notifications/:notificationId/read` 均被拒绝（`403 FORBIDDEN`）；接收人本人首次标记写入 `readAt` 与 `NOTIFICATION_READ` 审计，二次调用幂等返回首次 `readAt` 不覆盖                                                                                                                                                 |
| **`A29` `notification_enabled` 静默联动** | 默认开启时 `A32` 写入未读提醒；接收人经 `PATCH /api/v1/me/preferences` 关闭 `notificationEnabled: false` 后，冷却期满的新 `A32` 仍返回完全一致的 4 字段 `200` 响应（不泄露偏好）、重复触发仍返回 `429 REMINDER_COOLDOWN`，且 `notifications` 表不新增记录；此前已落库提醒在关闭期间仍可经 `A33` 查看与 `A34` 标记已读；重新开启 `notificationEnabled: true` 后，新 `A32` 恢复落库并出现在 `unreadOnly=true` 列表 |
