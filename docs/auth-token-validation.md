# 双令牌认证变更与验证

日期：2026-10-24。设计入口：[账号与会话](modules/auth.md)、[架构约定](architecture.md#62-登录会话)。

## 交付内容

- 注册和登录返回 JWT Access Token（最长 15 分钟）与随机 Refresh Token（会话最长 30 天）。新增 A30 `POST /api/v1/auth/refresh`；现共 30 项业务契约。
- 每个请求验签后查询会话，退出提交撤销后旧 JWT 立即失效。刷新在会话行锁事务中轮换，保留已消费摘要检测重放，重放撤销整个会话。
- `auth_refresh_tokens` 保存摘要、会话引用及消费时间；现共 14 张表、112 个字段。已审查生成的 `0001_dry_wendell_vaughn.sql`，迁移先撤销旧单令牌会话。
- 移动端仅持久化 Refresh Token；启动在线恢复并读取 `getMe`。JSON、图片上传和读取共用单次并发刷新，业务请求不自动重发，刷新结果不确定时要求重新登录。
- 会话版本防止旧登录/刷新响应恢复已退出会话，也防止旧请求的 401 或旧退出响应清除新账号。凭据删除失败在当前进程内阻止恢复，并向调用方报错。
- 新增服务端私有 `AUTH_JWT_SECRET` 配置，本地 `setup:env` 初始化缺失值，生产通过 Compose 注入。服务端依赖新增 `jose`，统一锁文件；移动端未增加原生依赖或配置。

## 环境与发布

本机未提交的服务端 `.env` 已初始化签名密钥；开发库已执行已提交 SQL 对应的新迁移。迁移后旧会话需要重新登录。没有更改或发布生产环境。

其他开发环境更新后运行 `pnpm setup:env`、`pnpm migrate:db`；生产需独立配置 `AUTH_JWT_SECRET` 并按既有备份、独立迁移、发布镜像流程部署。本文记录底层双令牌阶段。后续移动端页面、iOS 模拟器真实账号验证和最新测试结果见[移动端认证实现与验证](mobile-auth-validation.md)；仍未进行物理真机验收。
