## 安装、启动与登录

开发者按[成员环境配置](environment-setup.md)安装工具，在仓库根依次执行 `pnpm install --frozen-lockfile`、`pnpm setup`、`pnpm build:android`（iOS 使用 `pnpm build:ios`）、`pnpm dev:android` / `pnpm dev:ios`。首次必须先安装原生开发客户端；Expo Go、JS 导出均不代替此步骤。原生依赖、app config、config plugin 或原生资源变化后重新构建安装；仅文档或兼容的 JS 改动不要求重建。`dev` 不安装、不迁移，新迁移另跑 `pnpm migrate:db`。本机开发调试使用开发客户端；面向未配置开发环境的测试设备使用脱离 Metro 的独立 Release Android APK（见下节下载、校验与安装步骤），当前已上线公网 HTTPS 服务 `https://tongzhang.worldboot.net` 并发布 Day 6 独立包体 [`beta-day6-20261121`](https://github.com/Liangbai2333/tongzhang/releases/tag/beta-day6-20261121)，项目尚未发布应用商店签名包。

`apps/mobile/.env` 中 API 地址不带 `/api/v1`：iOS 模拟器用 `http://localhost:3300`；Android 模拟器用 `http://10.0.2.2:3300`，或 `http://localhost:3300` 配合 `adb reverse tcp:3300 tcp:3300`；物理真机经局域网使用电脑 IP。真机的 localhost 指手机自身，USB reverse 时才转向电脑。API 与 Metro 是两个端口，改变 API 地址/端口后重启 Metro并重新载入 App；端口转发在设备重启后重设。preview/production 必须使用 HTTPS，改变原生网络配置需要重建。详见[地址与配置](development.md#3-移动端地址与发布配置)；多人各用一台手机联调见[实机多人联调](multi-device-testing.md)。

首次打开欢迎页，点「开始使用」进入注册，填写用户名、邮箱、密码并同意协议；已有账号点「已有账号？ 登录」，填写邮箱或用户名及密码。注册/登录均连接真实 API。登录后在线读取账本列表。底部「账本」「我的」两个标签常驻，切换时淡入淡出，进入账本详情等页面后标签栏隐藏。「我的」顶部两张统计卡是入口：「我参与的账本」切到账本标签，「历史账本」打开个人归档列表；数量在线读取第一页，超过 50 本显示 50+。退出选择「退出登录」→「确认退出」，会清除本机凭据并尝试服务端撤销；保存的账目仍在服务端。若退出请求未获确认，不能据此宣称服务端撤销成功。

### 独立 Android APK 下载校验与安装

- **产物与前提**：通过 `EXPO_PUBLIC_API_BASE_URL=https://tongzhang.worldboot.net pnpm build:apk`（先可用 `pnpm build:apk --preflight --api-url https://tongzhang.worldboot.net` 自检，强制 `APP_VARIANT=production` 关闭原生明文 HTTP、拒绝回环地址与 `EXPO_PUBLIC_` 密钥、要求本机 JDK 17 与 `ANDROID_HOME`）执行 Prebuild 与 Gradle `assembleRelease` 打包内嵌 JS Bundle，输出 `dist/android/tongzhang-<shortSha>-standalone.apk` 与同目录 `SHA256SUMS.txt`（格式 `<64位小写SHA-256>  <文件名>`）。当前 Day 6 最新已核对包体发布于 GitHub Prerelease [`beta-day6-20261121`](https://github.com/Liangbai2333/tongzhang/releases/tag/beta-day6-20261121)（源码短哈希 `ef3cf86`，内嵌公网 HTTPS 地址 `https://tongzhang.worldboot.net`，见 [#169](issue169-b14-https-b20-ui-fixes.md) 与 [#173](issue173-standalone-apk-https-daily-check.md)；若 Day 7 `B21` 锁定新候选提交并重打包将同步更新）：
  - **APK 文件名**：`tongzhang-ef3cf86-standalone.apk`（`136,832,199` 字节）
  - **`SHA256SUMS.txt` 校验值**：`ece352d613919d11512b8cef74f3a711671d0d6f0065c50d9f42104f471fae54  tongzhang-ef3cf86-standalone.apk`
- **校验 `SHA256SUMS.txt`**（禁止跳过校验或安装哈希不匹配的 APK）：
  - Linux：`sha256sum -c SHA256SUMS.txt`（核对输出 `tongzhang-ef3cf86-standalone.apk: OK`）
  - macOS：`shasum -a 256 -c SHA256SUMS.txt`（核对输出 `tongzhang-ef3cf86-standalone.apk: OK`）
  - Windows PowerShell：`(Get-FileHash .\tongzhang-ef3cf86-standalone.apk -Algorithm SHA256).Hash.ToLower()`，逐位比对 `SHA256SUMS.txt` 中对应文件的 64 位小写哈希。
- **安装与启动**：
  - Android 真机直接安装：下载已校验的 APK 至手机，在系统提示允许安装未知来源应用后完成安装并直接打开，无需本机 Metro、数据库或 `adb reverse`。
  - ADB 安装（真机或模拟器）：执行 `adb install -r tongzhang-ef3cf86-standalone.apk`；若设备曾安装不同签名的旧开发客户端导致 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，先执行 `adb uninstall com.tongzhang.app` 再重新安装。
  - 启动核对：直接进入欢迎页注册或登录真实账号，确认直连内置 `https://tongzhang.worldboot.net` 读写账本；断网或服务不可达时应显示显式报错与手动重试，不展示离线假数据。

### 个人中心修改用户名与通知开关

在底部「我的」页的「账号设置」分组中提供以下入口：

- **修改用户名**：「账户信息」（右侧展示当前用户名）→ 打开「账户信息」面板（顶部提示“当前账号已在线核验”）。在「用户名」输入框中修改为 2～30 个有效字符（自动去首尾空格，不含空字符），值有变化时点「保存用户名」在线提交；保存后提示“用户名已更新，账本成员展示将同步刷新。”，并立即同步本地展示与失效账本/成员缓存（不递增账本或消费 `version`）。「邮箱」为只读展示并提示“邮箱暂不支持修改。”；面板底部保留「重新核验登录状态」。
- **通知偏好开关与站内提醒**：「设置」（右侧展示「通知已开启」或「通知已关闭」）→ 打开「设置」面板，顶部「通知」行附带「通知开关」（文案显示“已开启站内提醒通知”或“已关闭站内提醒通知”）。切换开关后直接在线按布尔绝对值保存；保存期间禁用交互，失败时在开关下方提示错误。该开关控制服务端待还催还提醒的入库静默策略（关闭后新催还不落未读列表，不影响既有历史提醒）。「账号设置」分组中的「站内提醒」（右侧标注「待还催还」，首页账本列表筛选栏右侧亦有「站内提醒」入口），点击打开「站内提醒」面板查看收到的待还催还提醒、切换「全部」/「仅看未读」筛选并点击标记已读直达对应账本结算页。「设置」面板同时提供「记账货币」（人民币 CNY）、「隐私说明」（点「查看」）与「用户协议」（点「查看」）；「关于同账」打开应用说明。

冷启动和从后台回到前台时需要在线核验：核验期间当前页面变暗并显示「正在核验登录状态」，核验失败才转为整页恢复界面。iOS 多任务界面、控制中心和系统弹窗不算进入后台，不会触发核验。断网会暂停登录状态，恢复联网后需要手动重新核验。断网/核验失败时使用界面的显式重试；恢复联网本身不会直接放行旧业务页面。会话刷新在业务请求发出前进行，不会在业务请求返回 401 后自动重发写操作。刷新响应丢失可能导致续期结果未知，需重新登录。

已登录页面遇到真实 401 或续期结果未知时，会清除失效凭据并显示「重新登录」门禁；存活进程中的原表单、所选图片/已上传引用和原提交尝试仍保留，底层页面不可操作。输入原账号密码，点「登录并继续」，只有该账号重新登录且在线 `getMe` 核验成功后才恢复。错误密码、仅登录成功但核验未完成、断网后的迟到成功响应都不会放行；恢复联网也不会自动提交。恢复后仍需按界面手动重试，必要时在线查看已保存结果。若使用其他账号登录，或点「放弃表单并返回登录」/主动退出，会清除原表单和查询内存。离开表单或进程终止后不保留草稿，重新登录后先在线核对既有结果。原生复测见 [#58/#59](issues58-59-final-acceptance.md#58t16--t27-正反路径) 和 [#60](issue60-native-candidate-validation.md#本轮实测与既有证据的边界)。

## 日常查看、分摊与邀请管理

列表默认显示本人未归档账本，包含进行中、结算中和已结清；「已归档账本」切换本人历史，「返回当前账本」切回。使用下拉刷新，有下一页时点「加载更多」。也可点「我的」里的「历史账本」统计卡进入历史列表。切换标签、从详情返回时页面会自动在线刷新，不显示刷新圈；只有手动下拉时才显示。列表读取失败使用手动重试，不能把空态当成接口失败或离线缓存。

账本详情可查看总消费、我的垫付/应摊/剩余净额、成员、消费列表及详情，操作栏提供「余额明细」「支出统计」与「结算」（冻结后为「结算记录」）。消费列表支持当前界面的筛选与加载更多；API 日期/付款人/类别筛选能力见接口索引，不能据 API 字段推定所有筛选组合都有 App 入口。

### 消费编辑与软删除

- **权限与冻结边界**：仅当账本处于 `ACTIVE` 状态且当前登录账号为该笔消费的记录人或账本创建者（`canEdit` 为 true）时，「消费详情」底部才会显示「编辑消费」与「删除消费」按钮。普通非记录人成员或账本已进入 `SETTLING`/`SETTLED` 状态时，底部不展示这两个入口。
- **编辑消费**：在「消费详情」点「编辑消费」，页面先在线核验账本成员与状态（若账本此时已进入结算或结清，显示“账本已冻结”并提供「返回消费详情」）。在「编辑消费」页可修改消费金额、消费名称、消费类别、付款人、日期、参与分摊与分摊方式（人均/按份/按金额）、备注，以及收据图片（可保留「已关联收据」、点「移除收据」删除、或经「从相册选择」/「拍摄收据」换绑新图，点按收据可打开「收据预览」）；编辑不修改记录人。若有未保存改动时返回，弹出「放弃未保存的修改？」面板，可选择「继续填写」或「放弃并返回」。点「保存修改」携带消费 `version` 与幂等键提交，成功后刷新详情并失效相关余额与统计缓存。
- **软删除消费**：在「消费详情」点「删除消费」，弹出「确认删除消费？」面板，展示消费名称、金额与日期并提示删除后不再计入账本总支出、成员余额与统计图表。点「确认删除」携带消费 `version` 与幂等键提交（或点「取消」关闭）；成功后刷新账本数据并返回。软删除没有撤销或恢复入口。
- **冲突与未知结果**：提交编辑或删除遇到 409 `VERSION_CONFLICT` 时提示记录已在其他设备/会话更新并提供「刷新最新消费」；遇到 409 `LEDGER_FROZEN` 时提示消费已冻结并提供「刷新账本状态」；均不自动重试。网络中断导致结果未确认时，编辑页提供「重试保存」与「回到账本查看」，删除面板提供「重试删除」与「回到账本查看」（期间禁用返回手势，重试复用原幂等键）。

消费付款人和分摊人分别选择，付款人可以不参与分摊；记录人是当前操作账号。输入元金额，最多两位小数；分摊面板支持人均、按份、按金额，先勾选成员再核对预览并应用。按份使用整数份数，按金额合计必须等于消费额。客户端预览只供核对，服务端保存时重新校验与计算；人均/按份余数按稳定成员 ID 分配。所引用的 Day6 主链原生实操覆盖两人人均，其他模式的自动化证据见 [#56](issue56-expense-image-validation.md)，不据此宣称本次原生实测。

### 记账页 AI 草稿回填

- **入口与边界**：仅限 `ACTIVE` 账本成员在新增消费页（「记一笔」）使用，编辑已有消费时不展示；表单存在未确认写入或提交中时禁用。点击顶部「AI 辅助填写」卡片中的「AI 生成草稿」打开当前页内嵌「AI 辅助填写」面板（不新建全屏路由）。支持输入「消费描述」（trim 后 1–500 字）和/或（表单已选收据时）使用「附带当前已选收据图片解析」开关（辅助标签「附带收据图片解析」，默认开启，解析时复用已选收据且保存时不重复上传），点「生成消费草稿」发起 `A31` 在线解析（移动端超时 30 秒，覆盖服务端默认 `AI_DRAFT_TIMEOUT_MS=15000`）。文本与收据均未提供时提示“请输入记账文本，或在表单中选择收据图片后再解析。”；收据上传未完成时保留当前输入并提示检查后重试或改用文字解析。服务端在 `repeatable read` 只读事务读取账本快照并返回经 `expenseDraftSchema` 二次校验的草稿，**绝不直写 `expenses`、不递增账本 `version`**。
- **回填与人工确认**：解析成功后关闭面板，仅将有效字段（标题、经 `@tongzhang/domain` `formatYuan(BigInt(...))` 整数分转换的金额、分类、日期、付款人、分摊方式与成员、备注、收据引用）回填至 `ExpenseForm` 可编辑状态；草稿为 `null` 的字段保留当前表单输入，非当前账本成员的分摊/付款人会被过滤并追加告警提示。表单顶部显示“AI 草稿已回填，请核对后手动点击「保存消费」”提示条（可点「收起」隐藏）及全部 `warnings`；必须由用户人工核对后手动点击「保存消费」走 `A13` 幂等落库。
- **降级与错误恢复**：服务端未配置模型凭据返回 `503 AI_DRAFT_UNAVAILABLE` 时保留当前输入，提示“服务端暂未启用 AI 辅助记账，已保留当前输入，请直接手动填写消费。”并仅提供「改用手填」；上游超时/异常或校验失败返回 `502 AI_DRAFT_UPSTREAM_ERROR` 或客户端断网/超时（`NETWORK_UNAVAILABLE` / `REQUEST_TIMEOUT` / `NETWORK_ERROR`）时保留当前输入与收据，按钮切为「手动重试解析」（亦可点「取消」改用手填）；遇 `409 LEDGER_FROZEN` 提示账本已冻结并提供「刷新账本状态」与「取消」；遇 `401 UNAUTHENTICATED` 走同账号核验门禁并保留表单输入，恢复后需手动重新发起解析；全链路不自动重试。

### 多维支出统计图表

- **入口与可见范围**：支持从账本详情操作栏点「支出统计」，或从「成员余额」顶部汇总卡点「查看支出统计」进入「支出统计」页。所有账本成员在 `ACTIVE`、`SETTLING`、`SETTLED` 及个人已归档状态下均可查看，支持下拉刷新；已软删除消费不计入统计。
- **展示维度与空态**：顶部展示账本名称、有效消费笔数、账本状态与「有效消费总额」。若账本无有效消费，显示「暂无消费统计」空态；有有效消费时依次展示四个模块：
  1. **「分类占比」**：SVG 环形图与各分类图例（按金额降序展示笔数、保留一位小数的百分比及金额；各项独立取整，百分比合计可能为 99.9%–100.1%）。
  2. **「按日消费趋势」**：可横向滚动的 SVG 柱状图（按日期升序展示每日金额与月-日标签）。当有消费的日期超过 366 天上限（`dailyTrendTruncated` 为 true）时，卡片顶部提示“账本消费天数超过上限，当前仅展示最近 366 天的按日趋势。”，此时趋势合计小于账本总额。
  3. **「单笔支出排行」**：展示金额前 10 笔有效消费（标题标注“前 N 笔”），点击任意排行项可直接进入对应「消费详情」。
  4. **「成员收支对比」**：展示每位成员的「已付」「应摊」金额、净额及 SVG 横向对比条。

### 邀请管理与应用内扫码加入

ACTIVE 创建者可在成员面板进入「邀请一起记账」管理或重置邀请码；邀请码有效 7 天，重置使旧码失效，不移除既有成员。受邀成员在账本列表右上角 `+` →「加入账本」支持两种方式：

- **手输邀请码**：输入 6 位邀请码（不含 `0`、`1`、`I`、`O`，自动去空格转大写）→ 点「查看账本」核对预览。
- **应用内扫码加入**：点「扫码加入」请求相机权限，授权后打开「扫描邀请二维码」面板，扫描创建者邀请页展示的 `tongzhang:invite:v1:<6位邀请码>` 二维码；识别成功后自动填入邀请码并触发在线预览。扫描到非同账邀请码时在面板内报错，提供「重新扫描」与「改用手输邀请码」。
- **相机拒权回退**：拒绝相机权限时留在当前「加入账本」手输页，提示“未获得相机权限，请直接在上方输入 6 位邀请码加入。”；若系统禁止再次弹窗询问权限，同时显示「前往系统设置开启相机」按钮以便跳转系统设置。
- **预览与加入边界**：手输与扫码复用同一「确认加入这个账本？」预览面板与 12 人上限校验；已有成员显示「进入账本」，满员或账本已冻结时不可加入。确认加入遇过期、已重置、满员或冻结应按提示联系创建者处理，结果未确认时按面板提供的「重试加入」或「回到账本列表」核对，不能反复提交旧码。

正式记录可下拉刷新、复制整套方案或单笔信息；页面不再显示独立刷新按钮、批次编号和算法版本卡片。复制不代表转账；实际资金在应用外处理。只有该转账付款人或创建者可登记已还，收款人身份本身不授予登记权限。全部登记不自动结清，仍需创建者确认。若正式方案没有转账，冻结保存批次后直接 SETTLED。

### 结算页站内催还与提醒列表

- **发起待还催还（`A32`）**：仅当账本处于 `SETTLING` 且目标转账为 `PENDING`，且当前成员为该笔收款人或非付款人账本创建者时，结算页对应待还条目显示「提醒对方」按钮（付款人本人及无关成员不显示）。点击打开当前页内嵌「发送待还提醒」面板（`remind-confirm`，不新建全屏路由，展示 `付款人 → 收款人` 与金额），可选填 1–120 字「催还备注（选填）」（纯空白视作不填）并点「确认发送提醒」携带稳定 `Idempotency-Key` 提交（或点「取消」关闭）。成功后结算页底部提示“已发送站内催还提醒，6 小时内不可重复催还。”，催还仅产生站内提醒与审计，**不修改原消费、转账金额、剩余净额或账本 `version`**。
- **6 小时冷却、隐私边界与失败恢复**：同一笔转账成功后按响应的 `cooldownEndsAt` 进入 6 小时冷却窗口，结算页按钮切为禁用态「已催还（冷却中）」；冷却期内重复催还返回 `429 REMINDER_COOLDOWN`，面板内联提示“该笔待还转账仍在 6 小时催还冷却期内，请冷却结束后再手动发起。”并隐藏发送按钮。服务端按付款人 `A29` 通知偏好决定是否落库未读提醒（关闭时静默不入未读列表但同样计入冷却），响应与提示文案**绝不泄露付款人是否关闭通知**。遇网络超时、断连、5xx 或无效响应进入不确定态时，锁定输入与关闭并保留原备注与原 `Idempotency-Key`，提供「手动重试催还」与「刷新结算页核对」（核对若仍为 `PENDING` 则保留面板提示手动重试复用原键，若已非 `SETTLING`/`PENDING` 则刷新关闭）；若重试后收到服务端终态拒收（`409 LEDGER_STATE_INVALID`、`409 IDEMPOTENCY_CONFLICT`、`404 TRANSFER_NOT_FOUND`、超 24 小时 `RETRY_WINDOW_EXPIRED`，或在不确定态重试时返回 `429 REMINDER_COOLDOWN` / `403 FORBIDDEN`），立即解锁关闭并提供「刷新结算页」；遇 `401` 门禁同账号核验后保留备注与原键，需手动再次确认发送；全链路不自动重试。
- **站内提醒列表与已读（`A33` / `A34`）**：可在底部「我的」→「账号设置」→「站内提醒」（右侧标注「待还催还」）或首页账本列表筛选栏右侧「站内提醒」打开「站内提醒」面板（不新建全屏路由）。仅展示当前登录账号收到的站内催还提醒，每次打开即时在线刷新（`staleTime: 0`，发起人经 `A28` 改名后重开即可看到最新用户名）；支持「全部」/「仅看未读」（`unreadOnly`）筛选、右上角「刷新提醒」与游标分页（「加载更多」，翻页失败显示「重试加载更多」；空态分别为「暂无站内提醒」/「暂无未读提醒」）。点击未读条目先调用 `A34` 标记已读（条目状态显示「处理中」并加同步连点锁，仅接收人本人可操作，重复标记保留首次 `readAt`），成功后关闭面板直达对应账本结算页（`/ledgers/[ledgerId]/settlement`）；点击已读条目直接跳转不重调 `A34`。首屏加载失败提供「手动重试」/「刷新提醒」，标记已读失败保留当前面板内联报错且不跳转、不自动重试；切换账号或退出时清空列表缓存、重置局部筛选并拦截过期在途回调。本版本仅提供站内提醒，不接入 APNs/FCM、短信或邮件催收（`X05` 零点边界）。

## 图片权限与失败恢复

已引用的 Android 实操中，系统相册仅向 App 提供所选照片，其他平台的权限范围和界面由系统决定；不要宣称所有系统都必须弹出全相册授权。封面从相册选择；收据可从相册选择或请求相机权限拍摄，拒绝相机权限可改用相册。取消/拒权保留当前输入与旧选择；Day6 相册取消和相机拒权增量证据见 [#60](issue60-native-candidate-validation.md#本轮实测与既有证据的边界)，成功上传/授权读取见 [#58/#59](issues58-59-final-acceptance.md)，成功拍照仍未验收。

选择后转换/压缩成 JPEG，长边不超过 2048、单图不超过 1 MiB；不能处理时重新选更小的图。收据最多一张。点击保存（或在 AI 辅助填写中勾选附带已选收据解析）时上传图片，点击保存才进行业务绑定；上传成功不等于创建账本/消费成功。图片保存独立 bytea 表，业务仅保存引用；未绑定仅上传者可读，绑定后仅账本成员可读，归档后仍检查成员权限。图片不是公开 URL，知道 ID 不授予读取权限。

| 情形                              | 用户操作与系统边界                                                                                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 选图/压缩或上传失败               | 查看当前页错误，修正权限/网络/图片后显式再点保存。已确认上传成功的 imageId 在本页保留并复用，不重复上传                                                                                  |
| 图片读取失败                      | 使用图片区域的「重试」；不应切成公开地址绕过认证                                                                                                                                         |
| 明确的校验/权限失败               | 先修正输入或角色；401 重新登录。冻结后不能用重试恢复新增消费权限                                                                                                                         |
| 401 或续期结果未知                | 在门禁「登录并继续」，同账号登录并在线核验后恢复内存输入、图片引用与原键；仍需手动重试。换账号或主动放弃清除原尝试，进程终止后不恢复                                                     |
| 网络超时、断连、5xx、返回格式错误 | 结果可能已提交。保留原页、原内容与原幂等键，按当前界面显式重试，或在线查看列表/详情核对结果；不要改金额换键重复新增。重试期间再断网也不会解除此前未知结果                                |
| 登记/结清/归档结果未知            | 按当前面板的重试/核对入口操作；只读查询确认已完成才关闭，未确认时保留原提交，可显式重试。暂未查到不等于之前一定没写入                                                                    |
| 冻结版本冲突                      | 重新在线读取预览，核对更新后版本/金额，再明确确认冻结；不自行把 expectedVersion 加一。已经冻结时读取正式批次                                                                             |
| 消费编辑/删除版本冲突或账本冻结   | 遇 409 `VERSION_CONFLICT` 点「刷新最新消费」核对最新内容后再操作；遇 409 `LEDGER_FROZEN` 点「刷新账本状态」，冻结后不可继续编辑或删除；不自动重试                                        |
| AI 辅助填写不可用或解析失败       | 503 保留输入点「改用手填」；502 或断网/超时保留输入与收据点「手动重试解析」或改用手填；409 冻结后点「刷新账本状态」；不写库、不自动重试                                                  |
| 待还催还冷却、状态冲突或结果未知  | 429 冷却期稍后手动再催（不泄露对方通知开关）；网络/5xx 不确定态保留备注与原幂等键，用「手动重试催还」或「刷新结算页核对」确认；遇终态冲突/404/429/403 解锁并点「刷新结算页」；不自动重试 |
| 离开页面/进程终止或超过 24 小时   | 当前尝试不会持久化；先登录在线核对列表、消费或正式记录，再决定下一步。客户端原尝试只允许 24 小时内重试；服务端成功幂等结果保存 7 天，两者不是同一时限                                    |
