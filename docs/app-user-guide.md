# App 操作手册

适用源码：`7616adb`（2026-10-27 远程 main，含 #48 验收成果）；本次文档不改变业务源码。新一轮双账号实操、原生客户端和证据版本见 [#49 逐项验收](issue49-documentation-validation.md)。接口开发者请看[当前接口索引](api-reference.md)，能力边界见[已知限制](known-limitations.md)。#20/#34 等旧记录只证明其注明的历史版本。

## 安装、启动与登录

开发者按[成员环境配置](environment-setup.md)安装工具，在仓库根依次执行 `pnpm install --frozen-lockfile`、`pnpm setup`、`pnpm build:android`（iOS 使用 `pnpm build:ios`）、`pnpm dev:android` / `pnpm dev:ios`。首次必须先安装原生开发客户端；Expo Go、JS 导出均不代替此步骤。原生依赖、app config、config plugin 或原生资源变化后重新构建安装；仅文档或兼容的 JS 改动不要求重建。`dev` 不安装、不迁移，新迁移另跑 `pnpm migrate:db`。本项目尚无对外发布的签名安装包或生产服务。

`apps/mobile/.env` 中 API 地址不带 `/api/v1`：iOS 模拟器用 `http://localhost:3300`；Android 模拟器用 `http://10.0.2.2:3300`，或 `http://localhost:3300` 配合 `adb reverse tcp:3300 tcp:3300`；物理真机经局域网使用电脑 IP。真机的 localhost 指手机自身，USB reverse 时才转向电脑。API 与 Metro 是两个端口，改变 API 地址/端口后重启 Metro并重新载入 App；端口转发在设备重启后重设。preview/production 必须使用 HTTPS，改变原生网络配置需要重建。详见[地址与配置](development.md#3-移动端地址与发布配置)。

首次打开欢迎页，点「开始使用」进入注册，填写用户名、邮箱、密码并同意协议；已有账号点「已有账号？ 登录」，填写邮箱或用户名及密码。注册/登录均连接真实 API。登录后在线读取账本列表。底部「我的」可读账号资料，打开关于、用户协议、隐私说明，或「重新核验登录状态」。退出选择「退出登录」→「确认退出」，会清除本机凭据并尝试服务端撤销；保存的账目仍在服务端。若退出请求未获确认，不能据此宣称服务端撤销成功。

冷启动、回到前台和网络恢复期间需要在线核验。断网/核验失败时使用界面的显式重试；恢复联网本身不会直接放行旧业务页面。401/会话失效需重新登录。会话刷新在业务请求发出前进行，不会在业务请求返回 401 后自动重发写操作。刷新响应丢失可能导致续期结果未知，需重新登录。表单只在当前页面内存中保留，退出、进程终止或身份失效后不能当成可恢复草稿。

## 两个账号完成一次共同记账

准备两个真实测试账号：甲为账本创建者，乙为普通成员。可在同一设备退出后切换，操作前核对「我的」中的用户名。以下示例由乙垫付 ¥120，两人各摊 ¥60，最终甲向乙登记 ¥60。使用当时 App 显示的邀请码；示例码不是长期可用凭据。

| 步骤             | 角色、入口与操作                                                                                                                                                             | 应看到的金额与状态                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1 自定义封面建账 | 甲：账本列表右上角 + →「创建账本」（辅助功能名「创建新账本」）；填名称，点「上传自己的封面图片」打开系统相册，选择测试图并完成系统选择，点「创建并邀请成员」                 | 上传 COVER 后创建并绑定；邀请页显示真实 6 位码、1/12 人。ACTIVE，version 1，总消费 ¥0。取消选图不会清空名称或旧选择      |
| 2 邀请码加入     | 甲将码提供给乙。乙登录后 + →「加入账本」→手输六位码→「查看账本」，核对名称、创建者、人数→「加入…」                                                                           | 预览不加入。确认成功后 2/12 人，ACTIVE，version 2。已有成员显示「进入账本」，不重复加入                                  |
| 3 消费与收据     | 乙：账本详情→「记第一笔」；金额填 `120`，名称填写测试消费；默认餐饮、当天、付款人为乙；「参与分摊」确认两人、人均，各 ¥60；补充信息→「从相册选择」→系统选择收据→「保存消费」 | 消费详情 ¥120，记录人/付款人均乙，两人各 ¥60，收据绑定。账本 ACTIVE，version 3。可点收据授权查看                         |
| 4 余额和预览     | 乙返回账本→「余额明细」；再返回→「结算预览」                                                                                                                                 | 乙垫付 ¥120、应摊 ¥60、净额 +¥60；甲垫付 ¥0、应摊 ¥60、净额 −¥60。一笔甲→乙 ¥60。预览不冻结，普通成员没有确认冻结入口    |

| 7 创建者结清     | 甲：全部登记且每人剩余净额为 0 后→「确认整本结清」→「确认结清」                                                                                                              | SETTLED，version 5。消费总额仍 ¥120，正式转账仍 ¥60，批次不变；结清后只读。乙无创建者结清权限                            |
| 8 个人归档与历史 | 甲：已结清正式记录→「归档账本」（详情也有「个人归档」）→「确认归档」；列表→「查看历史账本」或「已归档账本」                                                                  | 只写甲的 archivedAt，财务状态仍 SETTLED/version 5；甲当前列表移出、历史可读详情、消费、收据和同一正式批次                |

## 日常查看、分摊与邀请管理

列表默认显示本人未归档账本，包含进行中、结算中和已结清；「已归档账本」切换本人历史，「返回当前账本」切回。可下拉或点「刷新列表」，有下一页时「加载更多」。列表读取失败使用手动重试，不能把空态当成接口失败或离线缓存。

账本详情可查看总消费、我的垫付/应摊/剩余净额、成员、消费列表及详情。消费列表支持当前界面的筛选与加载更多；API 日期/付款人/类别筛选能力见接口索引，不能据 API 字段推定所有筛选组合都有 App 入口。消费详情的 `canEdit` 是权限信息，当前没有可用的消费修改/删除流程。

消费付款人和分摊人分别选择，付款人可以不参与分摊；记录人是当前操作账号。输入元金额，最多两位小数；分摊面板支持人均、按份、按金额，先勾选成员再核对预览并应用。按份使用整数份数，按金额合计必须等于消费额。客户端预览只供核对，服务端保存时重新校验与计算；人均/按份余数按稳定成员 ID 分配。本轮原生实操只覆盖两人人均，其他模式不能写成此次原生实测通过。

ACTIVE 创建者可在成员面板邀请/重置邀请码；邀请码有效 7 天，重置使旧码失效，不移除既有成员。二维码可展示、复制/分享邀请，但扫码加入尚不可用。预览成功后，确认加入仍可能遇到过期、已重置、12 人满员或冻结，应按提示联系创建者处理，不能反复提交旧码。

正式记录可刷新、复制整套方案或单笔信息。复制不代表转账；实际资金在应用外处理。只有该转账付款人或创建者可登记已还，收款人身份本身不授予登记权限。全部登记不自动结清，仍需创建者确认。若正式方案没有转账，冻结保存批次后直接 SETTLED。

## 图片权限与失败恢复

本轮 Android 系统相册仅向 App 提供所选照片，其他平台的权限范围和界面由系统决定；不要宣称所有系统都必须弹出全相册授权。封面从相册选择；收据可从相册选择或请求相机权限拍摄，拒绝相机权限可改用相册。取消/拒权保留当前输入与旧选择；本轮补验了相册，拒权/取消的原生证据属于 [#48 候选验收](issue48-native-candidate-validation.md)，成功拍照仍未验收。

选择后转换/压缩成 JPEG，长边不超过 2048、单图不超过 1 MiB；不能处理时重新选更小的图。收据最多一张。点击保存才上传并进行业务绑定；上传成功不等于创建账本/消费成功。图片保存独立 bytea 表，业务仅保存引用；未绑定仅上传者可读，绑定后仅账本成员可读，归档后仍检查成员权限。图片不是公开 URL，知道 ID 不授予读取权限。

| 情形                              | 用户操作与系统边界                                                                                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 选图/压缩或上传失败               | 查看当前页错误，修正权限/网络/图片后显式再点保存。已确认上传成功的 imageId 在本页保留并复用，不重复上传                                               |
| 图片读取失败                      | 使用图片区域的「重试」；不应切成公开地址绕过认证                                                                                                      |
| 明确的校验/权限失败               | 先修正输入或角色；401 重新登录。冻结后不能用重试恢复新增消费权限                                                                                      |
| 网络超时、断连、5xx、返回格式错误 | 结果可能已提交。保留原页、原内容与原幂等键，点「重试原提交/重试原消费提交」或在线核对；不要改金额换键重复新增。重试期间再断网也不会解除此前未知结果   |
| 登记/结清/归档结果未知            | 面板中「在线核对结果」只读查询，确认已完成才关闭；未确认时保留原提交，可显式重试。暂未查到不等于之前一定没写入                                        |
| 冻结版本冲突                      | 重新在线读取预览，核对更新后版本/金额，再明确确认冻结；不自行把 expectedVersion 加一。已经冻结时读取正式批次                                          |
| 离开页面/进程终止或超过 24 小时   | 当前尝试不会持久化；先登录在线核对列表、消费或正式记录，再决定下一步。客户端原尝试只允许 24 小时内重试；服务端成功幂等结果保存 7 天，两者不是同一时限 |

权限和原生配置说明同时参考 [Expo SDK 57 ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/) 与当前 [选图实现](../apps/mobile/src/features/images/receipt-files.ts)，不按旧版权限行为推定本轮结果。

图片上传本身不幂等：响应丢失时可能留下未绑定资产，不能承诺上传恰好一次。未绑定且无引用、超过 24 小时的临时图片由独立清理命令处理；不会成为消费或影响余额。App 无业务离线缓存、持久草稿或写入自动重试队列。
