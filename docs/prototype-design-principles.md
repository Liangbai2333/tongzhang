# 同账 TongZhang 原型设计目标与原则

日期：2026-10-14

适用范围：移动端 App 的页面、面板、交互状态及演示流程

同账面向旅行、聚餐等多人共同消费场景，帮助成员记录谁付款、谁分摊，查看应收应付，并完成结算与历史查阅。原型以“把共同账目记清、算清、留存”为目标，覆盖账本完整生命周期。

## 1. 设计目标

| 目标           | 具体要求                                                                             |
| -------------- | ------------------------------------------------------------------------------------ |
| 完整的业务闭环 | 串联注册／登录、创建账本、邀请加入、记账、查看余额、结算、登记已还、结清与个人归档。 |
| 易于理解的账目 | 明确区分付款人、记录人和分摊人；展示每人已付、应摊及应收／应付，说明谁向谁转账。     |
| 连贯的操作体验 | 在原页面完成选项设置、校验和反馈，减少重复页面与不必要跳转。                         |
| 清晰的财务状态 | 区分进行中、结算中、已结清；让用户知道当前能做什么，以及确认操作后的变化。           |
| 可供开发与验收 | 明确页面、覆盖面板、同页状态及返回来源；使用一致的示例数据演示主流程和关键分支。     |

首版以在线操作、人民币记账和最多 12 人的共享账本为边界。不设计浏览器版、真实支付、多币种、OCR、聊天或离线同步入口。

## 2. 信息组织原则

### 2.1 按用户任务组织功能

| 模块       | 用户需要完成的任务                                           |
| ---------- | ------------------------------------------------------------ |
| 账号       | 注册、登录、查看与修改账户信息。                             |
| 账本       | 创建与浏览账本，查看摘要、状态和消费流水。                   |
| 成员与邀请 | 复制或分享邀请码、应用内扫码加入、查看成员和创建者。         |
| 消费与分摊 | 记录消费、选择付款人和参与者、设置分摊、查看与修改记录。     |
| 余额与统计 | 查看成员应收应付、账本总支出、类别占比和成员已付／应摊对比。 |
| 结算       | 预览转账方案、复制文案、正式发起结算、登记已还。             |
| 结清与历史 | 确认整本结清、个人归档、查阅只读记录。                       |
| 个人与设置 | 查看个人信息、切换通知偏好、阅读协议。                       |

### 2.2 按决策重要性安排信息

- 账本详情先展示总支出与个人已付、应摊、净额，再展示工具入口和流水。
- 结算摘要展示待转账总额、账本总支出和转账笔数，明细展示双方、金额与登记状态。
- 金额、成员和状态优先于装饰与说明；重要金额不因长名称或窄屏被截断。
- 原始消费净额与登记后的剩余应收应付使用明确标签，不混用同一数值含义。

## 3. 交互设计原则

### 3.1 页面承载任务，面板承载局部操作

独立页面用于账本浏览、消费填写、分摊设置、余额统计和结算等完整任务。类别、付款人、日期、筛选、加入确认及风险确认优先使用底部面板或弹窗。

面板关闭后回到实际来源，保留原页输入、筛选条件和浏览位置。不同入口可复用同一功能，但不能固定返回某个示例页面。

### 3.2 反馈留在当前任务中

| 场景                       | 反馈方式                                                            |
| -------------------------- | ------------------------------------------------------------------- |
| 登录或表单校验失败         | 在原表单中提示；字段错误贴近对应字段，保留已输入内容。              |
| 页面加载                   | 内容区显示骨架或加载状态，保留导航结构。                            |
| 网络或加载失败             | 当前页显示原因和重试入口，不跳独立错误页，不用伪造的 0 元代替数据。 |
| 保存、删除、复制成功       | 原页更新或返回来源列表，以轻提示反馈。                              |
| 归档成功                   | 返回原账本列表，提示已归档，并提供“查看历史账本”入口。              |
| 冻结、删除、登记已还、结清 | 确认面板展示对象及后果，允许取消并回到原任务。                      |

业务读取和提交必须在线。网络失败时仅在当前表单内存中保留输入，供用户手动重试；不设计离线草稿或自动同步。写操作等待服务器确认后再显示成功，提交中避免重复点击。

### 3.3 同一任务只有一套设置流程

- “参与分摊”和“分摊方式”进入同一套分摊设置界面。
- 人均、按份、按金额在设置界面内切换，并直接展示每人应摊，不再增加重复预览页。
- “完成”只更新消费表单中的分摊摘要；“保存消费”才提交整笔记录。
- 按金额分摊显示已分配金额与差额，合计等于消费总额才能保存。
- 付款人可以不参与分摊；未选成员不承担该笔消费。

### 3.4 简单操作直接完成

- “分享邀请”直接打开系统分享面板，不先经过自定义分享选择页。
- 通知开关切换后即时保存偏好，失败时回退并提示，不设置额外“保存设置”按钮。
- 人民币作为固定信息展示，不表现为可选择币种的控件。
- 已结清页面的记录卡片直接展示登记时间，不再为相同内容增加历史结算记录页。

### 3.5 状态与权限决定可用操作

| 状态   | 界面行为                                             |
| ------ | ---------------------------------------------------- |
| 进行中 | 允许按权限记账、编辑和删除；结算预览不改变账本状态。 |
| 结算中 | 正式结算后消费只读，展示转账进度及允许的登记操作。   |
| 已结清 | 消费和结算记录只读，提供历史查阅与个人归档入口。     |

创建者标识明确；正式结算和整本结清由创建者操作。登记已还由该笔转账付款人或创建者操作。“全部已还”与“整本已结清”分别展示，归档仅整理本人列表，不改变账本财务状态。

## 4. 视觉设计原则

### 4.1 强调色具有明确用途

整体采用浅色背景、白色信息卡和深色正文，通过字号、留白与分隔建立层级。黄色主要用于当前任务的主操作及少量选中状态。

| 视觉角色   | 使用规则                                                           |
| ---------- | ------------------------------------------------------------------ |
| 白底       | 账本列表、金额摘要、成员明细、转账记录等常规信息。                 |
| 实黄       | 创建、保存、记一笔、确认结算等主操作；不作为普通信息卡的默认底色。 |
| 浅黄       | 冻结提醒等需要注意的说明，或有明确选择语义的局部选项。             |
| 绿色／红色 | 应收／应付、完成／异常，始终搭配文字标签。                         |
| 图表配色   | 用于区分类别或数据系列，图例与图形一致，跨页面含义稳定。           |

账本列表统一白底，以小标签区分状态；不把第一张账本默认画成已选中。账本详情、成员余额和结算摘要采用白底，突出金额。封面选中保留浅底与描边即可，不叠加多重强调。

### 4.2 图标统一且不重复

- 使用统一的线性图标，保持笔画粗细、曲线、端点与视觉重量一致。
- 同类用途使用相同尺寸、配色和容器；导航操作、表单图标与功能入口分别遵循统一规格。
- 普通操作图标以中性色为主；选中、警示或异常才使用相应语义色。
- 图标底色用于区分必要的功能入口，不给所有图标默认加黄色底块。
- 同一表单字段不在标签与输入框内重复放置同义图标；同组设置行全部采用相同的有图标或无图标形式。
- 图标不替代必要文字；独立图标按钮具有明确的操作名称。

### 4.3 文案服务于操作

- 使用“待转账总额”“转账笔数”“登记已还”等明确标签，避免反复使用大字号宣传句。
- 笔数和金额随数据变化，不固定显示“两笔转账，就算清”。无需转账时展示 0 笔、0 元及结清入口。
- 按钮说明具体动作，错误提示说明可采取的下一步。
- 不重复解释已由标题、字段和按钮表达的内容；只在金额规则、权限或不可逆后果处保留必要说明。
- “登记已还”表示人工记录，不使用“支付成功”或“到账验证”等容易误解的表述。

## 5. 移动端适配与原型组织

- 内容适应不同屏幕、系统安全区域与键盘；主要操作不被遮挡。
- 长账本名、消费名、大金额及大字号状态不造成关键信息重叠。
- 触控区域与图标视觉尺寸分开处理，避免小图标难以点击。
- 应收应付、错误和选中状态同时使用文字或形状，不能仅依赖颜色。
- `Screens` 按功能分类展示页面、面板及状态，使用唯一编号，不设置演示连线。
- `Prototype Flow` 连接完整主路径与关键分支；`Icons` 保存统一图标资源。
- 用画板模拟的同页状态不等于独立 App 路由；设计说明标注页面、覆盖面板、状态及返回来源。
- 静态数据、复制反馈、系统分享示意及相机示意与真实设备能力明确区分。

## 6. 设计验收标准

| 检查项   | 通过条件                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 主流程   | 能从注册／登录进入“鼓山一日”，演示邀请三名成员、记账、查看结算并复制方案，继续完成登记、结清和归档。 |
| 示例一致 | 三笔消费总额 ¥300；四人净额为 +¥30、+¥60、−¥30、−¥60；示例方案为小陈→小安 ¥30、小丁→小白 ¥60。       |
| 分支完整 | 包含部分参与、按份、按金额、筛选无结果、加载失败、邀请码异常及无需转账等状态。                       |
| 交互连贯 | 关闭面板回到来源；错误保留输入；成功反馈不增加无意义的全屏页面。                                     |
| 状态清晰 | 预览不冻结、正式结算后只读、全部登记后由创建者结清；还款不计入消费总支出。                           |
| 视觉一致 | 同类卡片、按钮和图标遵循统一规则；强调色不与主操作争夺注意力。                                       |
