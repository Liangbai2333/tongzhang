## 2. 已合入 `B18` 实测与 `B22` 前置交付材料账务守恒复核

针对当前 `origin/main`（`58707d5`）上已合入的 `#174`（`B18` 独立 APK 四人 `30000` 分“鼓山一日”实测）与 `#176`（`B22` 交付契约链接审计脚本），按统计与结算模块主作者口径完成账务守恒与交付一致性复核：

1. **云端 PostgreSQL 17 守恒快照复算**（原始记录见 [cloud-db-conservation-snapshot.txt](evidence/issue174/cloud-db-conservation-snapshot.txt) 与 [issue174-b18-gushan-and-b19-survey.md](issue174-b18-gushan-and-b19-survey.md)）：
   - **软删除排除与总额守恒**：有效消费 3 笔（食堂 `12000`、鼓山门票 `12000`、车费 `6000`）= `30000` 分；已软删消费 `Gushan ticket`（`14000` 分、`version = 2`）被严格排除；有效分摊 `10` 行合计 `30000` 分，与有效消费总额完全相等。
   - **成员净额与最少转账复算**：
     - `小安`：已付 `12000`、应摊 `3000 + 3000 + 3000 = 9000`、净额 `+3000`；
     - `小白174`：已付 `12000`、应摊 `3000 + 3000 = 6000`、净额 `+6000`；
     - `小陈`：已付 `6000`、应摊 `3000 + 3000 + 3000 = 9000`、净额 `-3000`；
     - `小丁`：已付 `0`、应摊 `3000 + 3000 = 6000`、净额 `-6000`；
     - 全员净额之和 `+3000 + 6000 - 3000 - 6000 = 0`；`zero-sum-dp-v1` 精确 2 笔转账（`小陈 → 小安 3000`、`小丁 → 小白174 6000`），`transfer_total_cents = 9000`、`transfer_count = 2`，均登记 `PAID` 后全员剩余净额归零。
   - **版本号与个人归档隔离**：`ledgers.version = 12`（建账 1 → 3 人加入 4 → AI 录入 5 → 编辑 6 → 软删 7 → 3 笔有效消费 10 → 冻结 11 → 结清 12），确认 `TRANSFER_REMINDED`、2 笔 `TRANSFER_PAID` 与 `LEDGER_ARCHIVED` 均未递增 `version`；`小安` 归档（`archived = t`）不影响其余 3 位成员（均 `archived = f`）及账本 `SETTLED` 终态。
2. **`B22` 交付契约与链接审计复核**（[issue176-docs-sync-and-delivery-audit.md](issue176-docs-sync-and-delivery-audit.md)）：
