# 登录、权限与幂等自动化回归

日期：2026-10-24。关联 [Issue #6 / T15](https://github.com/Liangbai2333/tongzhang/issues/6)，公共能力依赖 [Issue #2 / T04](https://github.com/Liangbai2333/tongzhang/issues/2)。本轮按用户确认一并补齐必要基础能力，使用 `Refs #2` / `Refs #6`，不提前关闭整项任务或扣减点数。

## 测试数据与真实边界

所有数据库测试必须显式设置 TEST_DATABASE_URL，统一 guard 拒绝非 PostgreSQL 地址和名称不以 `_test` 结尾的库，报错不输出凭据。全局 setup 在并发测试开始前对目标测试库应用已审查迁移，解决空库中账号请求与建表竞争的问题。可复用 fixture 通过真实注册 HTTP 接口创建 UUID 邮箱账号，按需在测试库准备账本/成员夹具；清理只删除本 fixture 跟踪的用户、账本、会话、审计和幂等记录，无全库 TRUNCATE，不操作开发业务表。

认证测试使用正式注册、登录、刷新、退出和 getMe 路由；成员拒绝使用正式账本详情/成员路由。完整幂等测试使用只在测试中注册的 HTTP 适配器，调用正式鉴权、成员校验、事务及 executeIdempotent，真实写入 PostgreSQL 账本版本、审计和结果表。适配器不进入生产应用；这些结果证明公共基础能力及事务语义，尚不代表正式创建账本、记账或结算接口已接通。

## 独立预期与覆盖

| 场景                           | 固定预期与实际断言                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 正确/错误/未知账号，重名用户名 | 正确账号 200；错误或未知账号 INVALID_CREDENTIALS / 401；重名用户名 ACCOUNT_AMBIGUOUS / 409                    |
| 会话与双令牌                   | 轮换不延长绝对到期；重放提交撤销；并发刷新与退出最终撤销；退出后旧 JWT / Refresh Token 拒绝，另一会话不受影响 |
| 匿名、非成员、不存在的账本     | 匿名 UNAUTHENTICATED / 401；非成员及不存在的账本 FORBIDDEN / 403，不泄露账本名称                              |
| 成员与创建者                   | 从实际表取得身份与 ACTIVE 状态；普通成员不能通过创建者策略；未实现业务仍明确 501                              |
| 同键同内容                     | HTTP 成功体逐字段相同；账本 version 由 1 到 2，审计 1 条，幂等结果 1 条                                       |
| 同键不同内容                   | IDEMPOTENCY_CONFLICT / 409；version、原名称、审计及结果计数不变                                               |
| 四个并发相同请求               | 四个 200、成功体一致；version 只增加一次，审计和结果各 1 条                                                   |
| 并发不同内容                   | 恰好一个 200、一个 409，只有一份业务/审计效果                                                                 |
| 回调失败或结果不可 JSON 序列化 | 业务版本、审计、成功结果均回滚；用户显式重试原键可以成功                                                      |
| 用户/资源隔离、权限变化、过期  | 相同 UUID 键按用户及资源路径隔离；撤销成员身份后不能重放成功；重放不续期，过期记录按规则替换                  |
| 请求摘要与测试库保护           | 对象键顺序不影响摘要；数组顺序和数值/字符串有别；拒绝循环、bigint、NaN 等非法输入；拒绝开发库且错误不含秘密   |

## 实际运行

在本机 PostgreSQL 17.11 的独立测试库运行；另创建临时空白 `_test` 库验证全局迁移、并行测试及清理，结束后删除该临时库。命令：显式设置 TEST_DATABASE_URL 后执行 `pnpm test:integration`。最终 5 个数据库测试文件、24 项通过；`pnpm test` 为 16 个文件、102 项无数据库测试通过。相关 UI/Provider 的双平台测试 46 项通过，详见 [公共反馈组件验收](common-feedback-validation.md)。

测试命令输出以 Vitest 的文件/通过计数核对；失败诊断包括公共能力缺失（补齐 #2）、首次加载超时（已有 CI 修复记录）及本轮测试开发中的 macOS 临时目录真实路径差异、无障碍元素标记/匹配器问题，均修复后重跑。数据库闭环、业务金额/状态与正式写入接口的后续回归仍属于 T15 / T26 范围，不能据此关闭整项任务。
