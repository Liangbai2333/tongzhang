# 公共状态组件与登录复测

日期：2026-10-24。关联 [Issue #5 / T28](https://github.com/Liangbai2333/tongzhang/issues/5)，与 T16 验收衔接，使用 `Refs #5`。本轮交付登录可复用的公共控件及局部复测，后续账本/记账/结算异常场景未验收，不扣减整项点数。

## 组件接口与接入

- `src/components/Feedback.tsx` 提供 InlineError、RequestState、EmptyState 和 requestErrorMessage。InlineError 统一可访问的字段/请求错误；RequestState 在原容器显示加载、错误与显式重试；未知异常用安全回退文案，避免把内部错误细节直接给用户；EmptyState 只展示调用方提供的真实空态或未就绪说明。
- 登录/注册、Field、会话恢复及账号页已接入。沿用既有 Figma 的暖白背景、字色、文本尺度、卡片及按钮，不新增路由或业务数据。已有 Button 的 loading/disabled 状态继续作为提交中禁用接口，重复提交仍由表单与认证 controller 共同阻止。
- 重试只响应用户点击；组件无请求 effect，不建离线队列或自动重试写入。注册未知异常使用“暂时无法创建账号”，不误报登录动作。

## 复测结果

| 用例           | 预期                                             | 实际                                                                            |
| -------------- | ------------------------------------------------ | ------------------------------------------------------------------------------- |
| 空登录表单     | 原页显示账号/密码字段错误，不发送登录            | 原生 iOS 与双平台测试通过                                                       |
| 错误/未知凭据  | 显示真实接口错误，账号密码保留，可修正后手动提交 | iOS 对 qa-unknown@example.test 的真实请求返回“账号或密码错误”；未创建账号或会话 |
| 断网/接口失败  | 原表单保留输入，不自动重交                       | 网络替身的组件测试通过；再次点击才发第二个请求                                  |
| 提交中连点     | 不重复发请求，输入/返回禁用                      | 既有真实表单行为测试与公共 Button 测试通过                                      |
| 加载/恢复失败  | 当前容器显示进度与原因，显式核验入口可用         | 公共状态及 Provider 双平台测试通过，等待中不显示重试按钮                        |
| 异常隐私与空态 | 未知异常不泄露细节；功能未接通不伪造零余额       | 公共组件测试通过                                                                |
| 返回与阅读面板 | 保留当前表单；返回欢迎页后清理本轮输入           | 自动化阅读面板及 iOS 返回复测通过                                               |

`pnpm test:mobile`：iOS / Android 共 10 个套件、46 项通过；图标/网络/存储替身只用于组件测试，不冒充原生接口验证。本轮修复 ActivityIndicator 缺少显式 accessible 标记的问题，并使用当前测试库支持的角色 busy 查询验证提交状态。

实际设备：iPhone 17 / iOS 27.0，SDK 57 现有开发客户端及 Metro；请求本机真实 API :3300 与 PostgreSQL 开发库。只发送负向登录请求，未注册新账号；表单输入在返回欢迎页后已清理。仅新增 [一张原生失败态截图](evidence/common-feedback/login-error.png)，保留此前注册、恢复、撤销、退出的[真实验收记录](mobile-auth-validation.md)作为正反用例基线。

本轮没有原生依赖/配置变化，没有重建开发客户端；未进行 Android 原生安装、物理真机、大字体及真实设备断网人工验收。双端 JS 导出及 Expo Doctor 通过用于兼容性检查，不能替代这些验收。
