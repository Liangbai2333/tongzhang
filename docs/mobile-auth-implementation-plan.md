## 实施顺序

1. **访问守卫与恢复状态。** 根据架构的 `(auth)` / `(app)` 分组组织路由。冷启动显示原入口内的恢复状态，完成刷新与 `getMe` 后才放行；离线或读取失败在当前容器显示手动重试，不新增全屏错误路由。认证结果驱动跳转，避免仅因登录 Promise 返回就进入业务页。补充前后台切换、网络恢复与服务端撤销后的在线核验，不能自动重试业务写操作。
2. **登录与注册表单。** 使用 React Hook Form 和共享 Zod 约束；登录支持邮箱或用户名，注册包含用户名、邮箱、密码、确认密码和协议勾选。调用 `useAuth().login/register`，只有成功保存凭据并在线获取用户才进入受保护区域。失败保留输入，密码不日志化或持久化；提交期间禁用重复提交。协议内容与阅读行为按 T08 的交付接入。
3. **登录后落点。** 接入真实 `getMe` 展示当前用户与可用操作，保留登录/退出的可验证入口。账本服务仍返回 501 时展示功能未就绪的真实状态，不显示伪造账本、零余额或登录成功的设计样例，也不将预览页作为认证后的业务首页。待账本模块就绪后接入架构约定的账本导航。
4. **退出与失效。** 退出确认使用页面内面板，在线请求服务端撤销后清理凭据、查询缓存并卸载用户界面。断网、撤销请求失败或本地凭据清理失败时准确反馈结果；清理导致跳转后也要保留反馈，不能显示“服务端已退出成功”。任一受保护请求返回 401 时回到登录入口，返回键和旧链接不能重新进入业务区。
5. **交互与自动化验证。** 补充表单、Provider、路由守卫及退出反馈测试；网络/存储替身只用于相应自动化测试。真实数据库用例使用专用 `TEST_DATABASE_URL`。最后在原生客户端执行下方验收矩阵，保留版本、操作、结果和截图。

页面实现放 `apps/mobile/src/features/auth/screens`；共享视觉控件放 `src/components`；全局会话和恢复继续由 `src/providers/AuthProvider.tsx` 管理。路由放 `apps/mobile/app`，协议、退出确认、错误和加载状态都不独立建全屏路由。

## Issue #1 验收矩阵

| Issue 验收项 | 原生操作与预期                                                                                       | 证据                               |
| ------------ | ---------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 真实登录     | 正确账号登录，真实 `getMe` 返回本人；错误密码显示契约错误并保留输入，不能跳成功页                    | 原生截图、真实 HTTP/数据库验证结果 |
| 重开在线核验 | 登录后结束并重开 App；通过 SecureStore 中的 Refresh Token 在线刷新，再获取用户；网络失败不得绕过守卫 | 冷启动、离线和手动恢复的操作记录   |
| 失效后拦截   | 服务端撤销或令牌过期后访问受保护入口，应回登录，返回键/旧地址不可绕过；其他会话不被误删              | 401 结果、原生导航截图             |
| 提交与输入   | 连点只发一次提交；断网、超时、错误凭据及邮箱重复保持当前输入；写操作无自动补交                       | 表单/请求测试与原生操作记录        |
| 退出即时撤销 | 退出后原 Access Token 和当前 Refresh Token 均被服务端拒绝，用户查询清空；退出取消不改变会话          | 退出前后真实请求与本地行为记录     |
| 退出失败反馈 | 断网或服务端失败时本地凭据尽力清理，明确服务端撤销未确认；不伪称已完成远端撤销                       | 原生提示与失败用例                 |
| 页面可用性   | 窄屏、键盘、密码显隐、长错误、大字体、面板关闭与返回来源可用                                         | 原生截图与人工核对结果             |
